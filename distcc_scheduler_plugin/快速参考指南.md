# 快速参考指南

## 🚀 30秒上手

```bash
# 1. 编译插件
cd distcc_scheduler_plugin && make

# 2. 使用 Random 算法
export LD_PRELOAD="$PWD/libdistcc_scheduler.so"
export DISTCC_ALGO=random
export DISTCC_PLUGIN_DEBUG=1
make -j8

# 3. 检查日志确认插件工作
# 应该看到: [distcc-plugin] Algorithm: RANDOM
```

## 📋 算法对比速查

| 算法 | 命令 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| **Native** | `DISTCC_ALGO=native` | 并发度最高 | 无调度控制 | 日常开发 |
| **Random** | `DISTCC_ALGO=random` | 简单、避免倾斜 | 负载不均 | 性能相近主机 |
| **RR** | `DISTCC_ALGO=rr` | 严格公平 | 忽略性能差异 | 同构集群 |
| **HEFT** | `DISTCC_ALGO=heft` | 负载感知、理论最优 | 依赖预测准确性 | 异构集群 |

## 🔍 常用命令

```bash
# 包装脚本使用（推荐）
./scripts/distcc_with_algo.sh --algo heft --debug -- make clean all

# 直接环境变量
export LD_PRELOAD="/path/to/libdistcc_scheduler.so"
export DISTCC_ALGO=rr
export DISTCC_HOSTS="host1:3641/8 host2:3642/4"
make -j8

# 清理状态
make -C distcc_scheduler_plugin clean

# 调试模式
export DISTCC_PLUGIN_DEBUG=1

# 检查插件加载
distcc --version  # 应显示插件初始化日志
```

## 🛠️ 故障排查

| 问题 | 检查方法 | 解决方案 |
|------|----------|----------|
| 插件未生效 | `echo $LD_PRELOAD` | 检查路径，重新设置 |
| 找不到主机 | `echo $DISTCC_HOSTS` | 确认主机配置正确 |
| RR状态混乱 | `ls ~/.distcc/scheduler*` | `make clean` 清理状态 |
| HEFT预测不准 | `cat ~/.distcc/compile_cache.txt` | 多次构建积累数据 |

## 📁 重要文件

- `libdistcc_scheduler.so` - 主插件库
- `~/.distcc/scheduler_state.dat` - RR/HEFT 状态
- `~/.distcc/compile_cache.txt` - HEFT 编译时长缓存
- `scripts/distcc_with_algo.sh` - 包装脚本
- `scripts/test_plugin.sh` - 功能测试

## 🎯 最佳实践

1. **开发时**：使用 `native` 获得最快编译速度
2. **测试时**：使用 `random` 验证算法切换
3. **生产时**：使用 `heft` 在异构环境获得最优性能
4. **调试时**：始终开启 `DISTCC_PLUGIN_DEBUG=1`
5. **状态管理**：定期 `make clean` 避免状态文件损坏
