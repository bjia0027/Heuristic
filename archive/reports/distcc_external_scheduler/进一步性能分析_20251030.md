### ⚠️ 主要瓶颈分析

根据测试日志和代码分析，剩余性能瓶颈包括：

1. **DAG自动推断仍然启用** ❌
   - 虽然禁用了遗传算法，但每个任务仍在尝试构建DAG
   - 逐任务调度模式不适合自动DAG推断
   - 导致大量重复计算

2. **特征提取I/O仍然频繁** ❌
   - 200个任务 × 多次调用 = 数千次文件读取
   - 缓存未在正确的对象中实现
   - `OnlineLinearRegression` 类缺少 `_feature_cache` 属性

3. **DAG提取失败但仍继续尝试** ❌
   - 日志显示大量"DAG覆盖率不足"警告
   - 每次失败后仍会继续尝试
   - 应该在首次失败后立即禁用

### 方案B: 修复特征缓存实现

**问题**: `_feature_cache` 在 `DAGHeuristicScheduler` 中定义，但 `OnlineLinearRegression.extract_features()` 中引用

**解决方案**: 将缓存传递给模型，或将特征提取移到调度器类中

```python
# 选项1: 在调度器中封装特征提取
class DAGHeuristicScheduler:
    def extract_features_cached(self, task, preprocessed_bytes=0.0):
        """带缓存的特征提取"""
        cache_key = (task.task_id, task.source_file)
        
        if cache_key in self._feature_cache:
            cached_features, cached_mtime = self._feature_cache[cache_key]
            if task.source_file and os.path.exists(task.source_file):
                current_mtime = os.path.getmtime(task.source_file)
                if abs(current_mtime - cached_mtime) < 1.0:
                    return cached_features
        
        # 调用原始提取
        features = self._compile_time_model.extract_features(task, preprocessed_bytes)
        
        # 缓存
        if task.source_file and os.path.exists(task.source_file):
            mtime = os.path.getmtime(task.source_file)
            self._feature_cache[cache_key] = (features, mtime)
        
        return features
```

## 💡 根本解决方案

**问题根源**: 启发式调度器设计用于**批量DAG调度**，但测试中使用了**逐任务在线调度**模式

**解决方案**:
1. 对于逐任务调度 → 使用简单调度器（Round-Robin, LeastLoaded）
2. 对于批量调度 → 使用启发式调度器（预先构建DAG，一次性调度所有任务）

### 正确使用方式示例

```python
# ❌ 错误：逐任务调度 + 启发式
for task in tasks:
    decision = scheduler.select_node(task, nodes)  # 每次尝试构建DAG

# ✅ 正确：批量调度 + 启发式  
all_tasks_dict = {t.task_id: t for t in tasks}
dag = build_dag_once(tasks)  # 一次性构建DAG
decisions = scheduler.schedule_dag_tasks(dag, all_tasks_dict, nodes)
```
