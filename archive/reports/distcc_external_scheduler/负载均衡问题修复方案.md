# 负载均衡问题修复方案

**问题发现时间**: 2025-10-29  
**状态**: 🎯 **根本原因已找到**

---

## ❌ 问题根因

### 现象

所有任务被分配到单个节点（node-1），负载均衡完全未生效。

### 根本原因

**混合本地/远程策略（`enable_hybrid_local_remote`）覆盖了HEFT的负载均衡决策！**

#### 证据（来自调试日志）

```
INFO - ✅ 任务 task_1 → node-2: EFT=1.00s  ← HEFT正确选择了node-2
DEBUG - 强制本地编译 task_1: 远端EFT=1.000, 本地EFT=2.000  
INFO -    📝 添加到schedule: task=task_1, machine=node-1  ← 被强制改成node-1！
```

#### 问题代码位置

`dag_heuristic_scheduler_optimized.py:2506-2507`

```python
# ✅ 混合策略：检查是否应该强制本地编译
if best_machine and self.enable_hybrid_local_remote:
    if self._should_compile_locally(task.compile_task):
        # 强制改成本地节点 ← 这里覆盖了HEFT的决策！
        best_machine = localhost_id
```

#### 为什么会这样？

1. **HEFT正确工作**: 负载均衡逻辑正确选择了node-2（负载低）
2. **混合策略覆盖**: `enable_hybrid_local_remote=True`（默认值）
3. **阈值过宽**: `local_remote_threshold=0.15`秒太大
4. **强制本地**: 即使远程节点更快，也被改成本地

---

## ✅ 解决方案

### 方案1: 在调度器初始化时禁用混合策略 ⭐ 推荐

**修改**: `dag_heuristic_scheduler_optimized.py:751`

```python
# 修改前
self.enable_hybrid_local_remote = True  

# 修改后  
self.enable_hybrid_local_remote = False  # 在分布式环境中禁用，避免覆盖负载均衡
```

**优点**:
- ✅ 简单直接
- ✅ 不影响其他功能
- ✅ 负载均衡优先

**缺点**:
- ⚠️ 失去本地编译的优化（但在真正的分布式环境中不需要）

---

### 方案2: 智能检测环境类型

**思路**: 自动检测是单机还是分布式环境

```python
def __init__(...):
    # 智能检测：如果有多个非本地节点，禁用混合策略
    self.enable_hybrid_local_remote = True  # 默认启用
    
def _initialize_dag_structures(self, dag, tasks, nodes):
    # 检测是否为真正的分布式环境
    non_local_nodes = [n for n in nodes 
                      if n.hostname not in ['localhost', '127.0.0.1', 'local']]
    
    if len(non_local_nodes) > 0:
        # 分布式环境，禁用混合策略
        self.enable_hybrid_local_remote = False
        self.logger.info("检测到分布式环境，禁用混合本地/远程策略")
```

**优点**:
- ✅ 自动适应环境
- ✅ 单机测试时仍可用本地优化
- ✅ 分布式时自动禁用

**缺点**:
- ⚠️ 需要修改代码
- ⚠️ 增加复杂度

---

### 方案3: 收紧阈值

**修改**: `dag_heuristic_scheduler_optimized.py:756`

```python
# 修改前
self.local_remote_threshold = 0.15  # 150ms阈值太大

# 修改后
self.local_remote_threshold = 0.01  # 10ms，更严格
```

**优点**:
- ✅ 保留混合策略
- ✅ 减少误触发

**缺点**:
- ❌ 治标不治本
- ❌ 仍可能覆盖负载均衡

---

### 方案4: 在HEFT中考虑负载惩罚

**修改**: 在混合策略检查时，考虑负载惩罚

```python
if best_machine and self.enable_hybrid_local_remote:
    if self._should_compile_locally(task.compile_task):
        # 检查本地节点是否过载
        localhost_load_ratio = ... 计算本地负载比
        
        if localhost_load_ratio < 1.3:  # 只有在本地不过载时才切换
            best_machine = localhost_id
        else:
            self.logger.debug(f"本地节点过载(ratio={localhost_load_ratio:.2f})，"
                            f"保持远程节点 {best_machine}")
```

**优点**:
- ✅ 综合考虑负载和本地性
- ✅ 更智能的决策

**缺点**:
- ⚠️ 代码复杂
- ⚠️ 需要仔细设计逻辑

## 🎯 总结

**根本原因**: `enable_hybrid_local_remote` 特性在分布式环境中不应启用，它会覆盖负载均衡的决策。

**最佳修复**: 将默认值改为 `False`，或在分布式环境中自动禁用。

**影响**: 修复后，HEFT的负载均衡优化将正常工作，任务会均匀分散到所有节点。
