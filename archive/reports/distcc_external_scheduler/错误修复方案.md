# DAG启发式调度器错误修复方案

## 🐛 问题分析

### 问题1: 大量文件解析失败 ❌

**错误信息**:
```
简单解析 /home/jia/桌面/distcc-3.4/test_projects/qtbase/build-min/src/tools/rcc/rcc_autogen/mocs_compilation.cpp 失败: 
[Errno 2] No such file or directory
```

**原因**:
1. 这些文件是**构建过程中生成的文件**（autogen, .qt/rcc等）
2. `compile_commands.json` 中包含了这些文件的编译命令
3. 但实际文件可能：
   - 还未生成（首次构建）
   - 被清理了（clean后）
   - 是临时文件

**影响**:
- 特征提取失败 → 使用默认特征
- DAG构建时无法读取文件内容
- 不影响调度功能，但会有大量警告日志

### 问题2: DAG覆盖率不足 ⚠️

**错误信息**:
```
DAG覆盖率不足: 0.0%, 缺失 1/1 个任务
```

**原因**:
1. **单任务调度模式** - 每次只传入1个任务
2. DAG提取尝试从整个项目构建DAG
3. 单任务ID与项目级DAG的task ID格式不匹配
   - 传入: `qtbase_task_1`
   - DAG中: `compile:/path/to/file.cpp`

**根本原因**: 
```python
# 测试代码逐个传入任务
for task in tasks:
    scheduler.select_node(task, nodes)  # 只传1个任务
    # ↓ 内部尝试构建完整DAG
    real_dag, real_tasks = extract_real_dag(...)  # 返回200个任务
    # ↓ 匹配检查
    current_task_ids = {task.task_id}  # {'qtbase_task_1'}
    real_task_ids = set(real_tasks.keys())  # {'compile:/path/...', ...}
    # ↓ 交集为空
    coverage = 0.0%  # 不匹配！
```

def _normalize_task_id(self, task_id: str) -> str:
    """标准化task ID以提高匹配率"""

    if task_id.startswith('qtbase_task_'):
        # 从任务对象获取源文件路径
        return task.source_file
    elif task_id.startswith('compile:'):

    return task_id
